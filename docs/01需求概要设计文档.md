## 1. 项目概述

### 1.1 项目背景

随着我国公共资源交易市场化改革不断深化，招投标领域面临着日益严峻的合规监管挑战：

**串标围标**：投标人之间相互约定中标或抬高报价的违规行为

**虚假资质**：伪造或篡改企业、人员资质证明

**关联公司围标**：关联企业协同围标，手段日趋隐蔽

传统人工审查方式存在以下问题：

| 问题 | 说明 |
|------|------|
| 效率低 | 大量投标文件审查耗时长 |
| 覆盖面窄 | 人工难以全面比对 |
| 标准不统一 | 审查尺度因人而异 |

### 1.2 建设目标

通过AI Agent、规则引擎和知识库等技术实现招投标文件的智能检测与辅助分析，提高工作效率，减少人工疏漏，为业务处理提供参考信息和证据支撑。

| 序号 | 目标 | 说明 |
|------|------|------|
| 1 | 围串标风险线索识别 | 基于大模型语义分析，自动识别多家投标文件间技术段落的文本相似、语义接近和异常一致性特征，为人工复核提供线索支持 |
| 2 | 资质有效性辅助核验 | 对人员资质、公司关联关系、证书有效期、时间一致性等进行自动提取、交叉比对和辅助核验 |
| 3 | 投标文件智能审查 | 对投标文件进行完整性、响应性、格式规范性等全面审查 |
| 4 | 招投标响应比对 | 建立招标要求与投标响应的映射关系，识别未响应、弱响应、偏离项 |
| 5 | 归档资料智能检测与辅助校验 | 对归档资料与招标文件进行时间一致性检查、企业公网信息核查、错别字检测 |
| 6 | 辅助评标参考 | 结合招标文件评分标准，对投标文件进行自动化评分分析 |
| 7 | 专家库随机抽取 | 提供一次性使用的专家随机抽取功能，保障评标公正性 |
| 8 | 档案管理与过程留痕 | 全流程记录审查、整改、归档过程，支持审计追溯 |
| 9 | 统计分析与监管协同 | 多维度统计分析项目风险、问题分布、整改情况，支持监管协同 |

### 1.3 建设原则

通过AI Agent、规则引擎和知识库等技术实现招投标文件的智能检测与辅助分析。

### 2.3 Agent 架构设计

#### 2.3.1 Agent 层次结构

| 层级 | 说明 | 技术实现 |
|------|------|----------|
| 主控 Agent (Coordinator) | 意图识别、任务分解、结果汇总 | LangGraph StateGraph |
| 专业 Agent | 文档解析、合规审查、比对分析、资质核验、风险识别、辅助评标 | LangGraph Agent |
| 共享 Skill | 可被多个Agent复用的能力 | Python Module |
| 工具 (Tools) | 底层能力调用 | FastAPI Tools |

#### 2.3.2 Agent 职责定义

| Agent | 职责 | 核心技能 | 职责边界 |
|-------|------|----------|----------|
| Coordinator Agent | 接收用户请求，识别意图，分解任务，调度专业Agent，汇总结果 | intent_recognition, task_decomposition | 统一入口，不直接处理业务逻辑 |
| 文档解析 Agent | PDF文件解析、OCR识别、文本提取 | pdf_parse, ocr_recognize | 仅负责文件到文本的转换，输出结构化文本供后续Agent使用 |
| 合规审查 Agent | 法律条文检索、合规性检查、问题识别 | law_retrieval, compliance_check | 核心：依据法律法规和招标规则检查投标文件合规性；边界：不进行文件间的比对 |
| 比对分析 Agent | 文本相似度计算、企业关系分析、评分 | similarity_analysis, graph_query | 核心：多份投标文件之间的一致性比对、投标vs招标文件的响应性比对；边界：不进行合规性判断 |
| 资质核验 Agent | 企业/人员/证书信息提取、有效期核验、外部数据交叉验证 | info_extraction, validity_check, cross_validation | 仅负责资质有效性核验，不进行合规性判断 |
| 风险识别 Agent | 围串标检测、异常风险识别、风险分级预警 | risk_detection, similarity_analysis, graph_query | 识别疑似问题，不直接定性 |
| 辅助评标 Agent | 评分标准配置、客观项分析、评分建议 | scoring_config, objective_analysis | 提供评分建议，不替代专家评审 |
| 专家抽取 Agent | 专家库管理、随机抽取、回避过滤 | expert_retrieval, random_selection | 仅负责抽取，不涉及评标其他环节 |
| 档案管理 Agent | 任务创建、流程跟踪、整改记录、报告归档 | task_management, archive_management | 全流程留痕管理 |
| 统计分析 Agent | 项目风险统计、问题分类、高频问题分析 | statistics_analysis, risk_summary | 仅提供统计分析结果 |

**Agent职责划分原则**：

- **合规审查 Agent**：侧重于"规则符合性"，如法规要求、招标文件规定的资格条件

- **比对分析 Agent**：侧重于"内容一致性"，如投标文件各部分是否一致、是否响应招标文件要求

- **资质核验 Agent**：侧重于"资质有效性"，如证书有效期、人员所属单位一致性

- **风险识别 Agent**：侧重于"异常检测"，如文本相似度、关联关系、报价离散度

#### 2.3.3 Skill 复用设计

| Skill | 功能 | 被哪些Agent使用 |
|------|------|----------------|
| law_retrieval | 法律条文检索 | 合规审查、比对分析、制度合规 |
| report_generation | 报告生成 | 所有Agent |
| notification | 通知推送 | 合规审查、比对分析、风险预警 |
| policy_retrieval | 制度检索 | 企业制度咨询、辅助决策 |
| similarity_calculation | 相似度计算 | 风险识别、比对分析 |
| graph_query | 图数据库查询 | 资质核验、风险识别 |

#### 2.3.4 Agent 与知识库映射

| Agent | 调用知识库 | 优先级 | 说明 |

| 类型标识 | 名称 | 内置 | 用途 |

## 3. 功能模块设计

### 3.1 模块一：文件智能解析（一期 P0）

#### 3.1.1 功能描述

对扫描件PDF招投标文件进行智能解析，提取文字、图表、表格、图片等内容。

#### 3.1.2 输入输出

| 项目 | 说明 |
|------|------|
| 输入 | 扫描件PDF招投标文件、Word文件、图片、压缩包 |
| 输出 | 结构化文本、识别出的图表/表格/图片、原文定位信息 |

#### 3.1.3 功能列表

| 二级功能 | 功能说明 | 优先级 |
|---------|---------|--------|
| 文件上传 | 支持招标文件、投标文件、归档资料等上传，支持单文件、批量、按项目/标段分类上传 | P0 |
| 文档格式识别 | 自动识别文件类型，如招标文件、投标文件、资格文件、技术文件、商务文件等 | P0 |
| GLM-OCR文字识别 | 对扫描件、图片件进行文字识别，提取正文和表格内容 | P0 |
| 文档结构化解析 | 自动识别目录、章节、标题、段落、页码、表格等结构信息 | P0 |
| 表格提取 | 自动识别文档中的表格内容并结构化提取 | P0 |
| 原文定位 | 对审查发现的问题支持页码级、段落级、表格单元格级定位 | P0 |
| 全文检索 | 支持对项目文件进行全文检索、关键词检索 | P1 |
| 解析结果校正 | 允许人工对识别或解析结果进行修正并保存 | P1 |

#### 3.1.4 性能指标

| 指标 | 要求 |
|------|------|
| 识别率 | ≥85% |
| 解析速度 | 1000页 ≤ 30分钟 |
| 支持格式 | PDF、Word、图片、压缩包 |

#### 3.1.5 Agent 协作流程

```
用户上传文件 → 文档解析Agent(文件格式识别) → 文档解析Agent(GLM-OCR/结构化解析)
     ↓
  结构化文本 → Coordinator Agent → 分发给后续专业Agent
```

| 修改建议生成 | 对检测出的问题给出修改建议或规范表达参考 | P0 |

| 修改建议 | 针对问题的修改建议 |

| 整改跟踪 | 问题整改状态、复查结论 |

|------|------|

## 8. 术语定义

| 术语 | 定义 |
|------|------|
| LangGraph | 基于LangChain的多Agent编排框架，支持复杂工作流、状态管理、循环/条件分支 |
| Agent | 智能体，能够自主完成特定任务的AI程序 |
| Skill | 可被多个Agent复用的能力模块 |
| Tool | 底层工具调用，如文件解析、数据库查询等 |
| API-first | 先设计API接口，再开发功能，确保外部系统可集成 |
| LLM | 大语言模型（Large Language Model），指具有大规模参数和计算能力的语言模型 |
| OCR | 光学字符识别（Optical Character Recognition），指对图像中的文字进行识别转换为文本的技术 |
| NLP | 自然语言处理（Natural Language Processing），指人与计算机之间用自然语言进行通信的技术 |
| 串标围标 | 投标人之间相互约定中标或抬高报价的违规行为 |
| 技术标 | 投标文件中的技术方案部分 |
| 商务标 | 投标文件中的报价部分 |
| 投标文件 | 投标人按照招标文件要求编制的响应性文件 |
| 招标文件 | 招标人向潜在投标人发出的邀请文件 |
| 弱响应 | 响应不充分、表达模糊、证据不足的响应内容 |
| 偏离项 | 与招标要求存在偏差的响应内容 |

## 附录：AI发展预留空间

**说明**：AI技术日新月异，架构设计需具备"前瞻性抽离"，预留以下三个空间、四项技术。

### 三个预留空间

#### 1 模型无关性架构 (Model-Agnostic)

设计建议：在 API Gateway 与 Agent 编排层之间增加一个 LLM Router (模型路由层)。

预留空间：未来如果出现比 Qwen3 更强的国产开源模型（如 Qwen4 或 DeepSeek 新一代），只需在路由层切换接口，无需改动任何 Agent 的业务逻辑。

#### 2 自进化 Skill 库 (Self-Evolving Tools)

设计建议：目前的 Skill 是固定的 Python 模块。

预留空间：预留一个"代码解释器 (Code Interpreter) Agent"。当面对全新的、未定义的审查规则时，Coordinator Agent 可以实时生成一段 Python 代码来处理特定的数据计算（如复杂的报价偏差率计算），实现 Skill 库的动态扩展。

#### 3 可解释性与溯源存证 (XAI & Traceability)

设计建议：增加"推理链条记录 (Thought Trace)"存储空间。

预留空间：随着 AI 监管法规（如《人工智能生成内容标识管理办法》）的完善，系统必须能复现 AI 判定"违规"的每一步逻辑。架构上应预留每个 Agent 的 thought_process 字段，并对接区块链或强审计日志，确保 AI 的决策在法律上"可解释、可追溯"。

### 针对特定违法违规的三项技术

#### 1 高仿/虚假资质

建议引入公网 API 实时联动，预留对接全国建筑市场监管公共服务平台（四库一平台）的接口，进行实时数据穿透校验，而非仅查阅库内旧数据。

#### 2 算法歧视/偏差

建议引入对抗性测试模块，预留一个"红队测试" Agent，专门模拟不同规模、不同地域的标书，检测主控 Agent 是否对特定背景的投标人存在评分歧视。

#### 3 系统安全幻觉

建议引入事实一致性评分 (FactScore) 在报告生成前，增加一个独立 Agent 对 AI 提取的每一个"事实"进行原位置回检（Citation Check），若无法在原件中找到对应坐标，则标记为疑似幻觉。
